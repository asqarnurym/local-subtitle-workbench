# Что входит в версию AIML и чем она отличается от журнальной (03.11.2026)

Назначение: быстро собрать курсовую статью AIML (русский язык, IMRAD), которая получит
полную оценку по рубрике силлабуса. Журнальная версия для SJ AITU остаётся полной.
Основание — `docs/IMPROVEMENT_PLAN.md` §9.3–9.5 и §10.1.

**Рубрика AIML** (§9.4):
- PO1, PO4 — воспроизводимость пайплайнов;
- PO4 — обоснованный выбор гиперпараметров;
- PO2 — качественные рисунки высокого разрешения;
- PO3 — критический обзор литературы за последние 5 лет, связанный с экспериментами;
- PO5 — документированный код и репозиторий.

Плюс уникальный набор данных и презентация на 10–15 слайдов.

## 2. Минимальная полная версия AIML, если S1b, S2 или S3 не успеют

Структура по образцу курса (`Vehicle_Type_Classification…docx`): Introduction →
Literature Review → Dataset → Framework and Implementation → Experimental Results →
Discussion.

1. **Введение:** проблема (синхронизация субтитров для доступности), RQ1–RQ3, вклад.
2. **Обзор литературы** (2021–2026 плюс первоисточники инструментов):
   - MFA, WhisperX, MMS, NFA, CTC-сегментация;
   - Rousso 2024 как внешняя опора;
   - пороги заметности рассинхрона ITU и EBU.
3. **Набор данных:** TIMIT 160, Buckeye 999 тестовых и обучающие дикторы для BRQE, длинные
   записи S1.
4. **Метод:**
   - пайплайн: VAD, Whisper, якорение, нарезка, MFA, BRQE;
   - сценарии A и B;
   - склейка стыков;
   - статистика;
   - воспроизводимость.
5. **Результаты:**
   - таблица RQ1 (все режимы) и рисунки E1;
   - RQ2: BRQE против константы, оценка надёжности, чувствительность к гиперпараметрам;
   - RQ3: таблица проверки C до и после склейки.
6. **Обсуждение:**
   - сравнение с литературой;
   - ограничения, включая недетерминизм MFA, выбор исправления на микротесте и то, что
     сценарий B ограничен ошибками текста Whisper;
   - будущая работа: S2, S3 (если не готовы), S4, S6.

Всё перечисленное уже посчитано и записано в репозитории. Эта версия закрывает PO1–PO5 без
результатов S1b, S2 и S3. Если прогоны успеют, каждый добавляет по одному рисунку и абзацу.

## 3. Чего не делать ради экономии

- Не убирать сценарий B и сравнение режимов: без них нет RQ1 и связи с литературой.
- Не выдавать незавершённые прогоны за результаты и не брать числа из микротеста: для
  статьи — только полная проверка C и завершённые прогоны.
- Не вставлять новые формулировки выводов без одобрения автора в CLAIM_LEDGER, в том числе
  находки RQ3 (`docs/S1B_MICROTEST_FINDINGS.md` §6).

## 4. Что можно убрать из методологии (04.11.2026)

Черновик: `docs/paper/aiml/AIML_draft_ru.docx`. Он не зависит от S2 и S3.

**Нужен ли S3.** Нет. **Решение автора 04.11.2026: в AIML S3 не входит**, принято до появления чисел S3. Прогон идёт для журнальной версии.
- Рубрика его не требует: обоснование гиперпараметров закрыто анализом чувствительности BRQE.
- §10.1 прямо разрешает сократить RQ4.
- Ценность есть, но она прикладная: какой Whisper достаточно для слабой видеокарты и что
  важнее для сценария B, покрытие или границы. Вопросы RQ1–RQ3 от него не зависят.
- Для журнальной версии он полезнее: это проверка устойчивости выбора large-v3.

**Главное правило.** Решение о S2 и S3 принимается по готовности к сроку, а не по результату.
Если прогон завершён и попал в статью, он публикуется при любом исходе. Убирать
предрегистрированный анализ, посмотрев на его числа, нельзя: это выборочная отчётность.

| Блок | AIML | Причина |
|---|---|---|
| S3 | Убран, пункт будущей работы | Не влияет на RQ1–RQ3 |
| S2 | Можно убрать; если готов, оставить раньше S3 | Прямо связан с вопросом о плотной речи и сбоях, но темп искусственный (вокодер) |
| Фонемы | Сократить до строки | RQ сформулированы в основном по словам |
| История S1 и `seam_safe`, абляция микротеста | Убрать, оставить проверку C | Промежуточные шаги; числа микротеста в статью не идут |
| Рисунки по фонетическим группам и длительности слов | Убрать | Описательные срезы |
| MF-1…MF-6 | Один пункт в будущей работе | Ничего не запускалось |
| Подробности R1–R3, журнал поправок протоколов | Один абзац | Рубрике достаточно описания воспроизводимости |

**Нежелательно убирать:**
- сценарий B и покрытие слов рядом с ошибкой;
- постоянную поправку как соперника BRQE;
- статистику по дикторам;
- отрицательный результат TIMIT (CLAIM-104): без него вывод о BRQE завышен;
- долю сбоев рядом с ошибкой на длинных записях (протокол S1, правило 3);
- вариант без якорей: это одна строка, а H5 без него не объяснить;
- разделение обучающих и тестовых дикторов и заморозку весов;
- ограничения: склейки, выжившие записи, запуск ядер вместо самих WhisperX и NFA.
