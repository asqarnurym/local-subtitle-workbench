# План инспекции уязвимостей и изоляции ошибок

Версия 17.11.2026. **Выполняется после подачи статьи DG 2027, по команде автора.** Сейчас это только план; ничего не запускалось.

## 1. Цель

1. Найти как можно больше мест, где модуль пайплайна ошибается или падает: условия срабатывания, симптомы, как часто.
2. Для каждого места понять, **куда ошибка распространяется**: на одно слово, на чанк, на всю запись, на другие модули.
3. Нейтрализовать ошибку или хотя бы изолировать её: ограничить ущерб минимальной единицей (слово → чанк → запись) и явно пометить.

Правило проекта «без фолбеков» сохраняется. Изоляция — это пометить пропуск и не дать ошибке испортить соседей, а не тихо подставить другой движок.

## 2. Метод

Для каждого модуля заполняется таблица в стиле FMEA (анализ видов и последствий отказов):

| Поле | Содержание |
|---|---|
| Вид отказа | Что идёт не так |
| Условие | Какой вход это вызывает |
| Симптом | Падение, тихий сдвиг, пропуск, неверный текст |
| Обнаружение | Как система это замечает сейчас (или не замечает) |
| Радиус поражения | Слово / чанк / запись / другой модуль |
| Текущая обработка | Что уже сделано |
| Мера | Нейтрализация или изоляция; тест |

Источники отказов, по возрастанию стоимости:

1. **Уже записанные отказы.** Все `benchmark_utterances.json` (frozen, S1, S1b, S2, S3, пилоты), `failure_audit.json`, `runtime_incidents.json`, `MFA_FAILURE_BACKLOG.md`, `AUTONOMOUS_RUN_20261106.md`. Бесплатно.
2. **Ревизия кода по модулям**: необработанные исключения, неявные допущения (монотонность, непустой вход, частота 16 кГц), пороги и константы.
3. **Расширение существующих стресс-скриптов** `scripts/adversarial_challenge.py` и `scripts/stress_reconcile.py` (нарезка и сшивка) на остальные модули; тесты на свойства (property-based) для инвариантов.
4. **Внедрение искусственных отказов** на обучающих дикторах и синтетике: тишина, обрезка, шум, клиппинг, темп, музыка, неверные или пропущенные слова транскрипта, дефисы и цифры, повторы слов, очень короткие и очень длинные входы. Мера — **радиус поражения**: сколько слов вне повреждённого места изменили границы больше чем на 20 мс.

## 4. Принципы изоляции (проверяются на каждом отказе)

- **Наименьшая единица отказа.** Ошибка слова не должна ронять чанк, чанк — запись (MF-2), клип — прогон.
- **Барьеры между модулями.** Каждый модуль проверяет вход (монотонность, диапазоны, непустой текст) и отвергает плохой вход явно, а не передаёт дальше.
- **Пометка вместо подмены.** Ненадёжные слова помечаются (голова надёжности BRQE, правдоподобие MFA) и попадают к человеку-проверяющему; время не выдумывается.
- **Защита соседей.** Исправление в одном месте не сдвигает правильные границы рядом (проверка радиусом поражения).
- **Различать научный отказ и инфраструктурный.** Второй останавливает прогон, а не становится строкой результатов (флаг `LSW_STRICT_INFRASTRUCTURE`).

## 5. Результат инспекции

- Реестр отказов (таблица §2 по всем модулям) с приоритетом: частота × радиус поражения.
- Для верхних позиций — мера и регрессионный тест. Меры, которые меняют результаты Proposed, оформляются как отдельное подысследование с протоколом; замороженные результаты не меняются.
- Связь с кандидатами `IMPROVEMENT_CANDIDATES.md` (G-6…G-9, G-18 и др.), чтобы не делать одно дважды.
