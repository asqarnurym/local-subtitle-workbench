> ASCII-дефис как blank ID 0. Наш tokenizer ошибочно включал его в targets,

> число кадров равно числу targets плюс числу соседних повторов (в том числе
> на границе слов). Независимое воспроизведение на synthetic emissions показало
> аварийный RuntimeError при старой неполной проверке. Теперь такой случай
> возвращает пустое выравнивание, как другие слишком короткие входы. Прежние
> успешные результаты не меняются; пересчёт не нужен.

## Общее

- **Модели и режимы** — замороженные: MFA english_us_arpa, веса BRQE `models/brqe`,
  постоянная поправка.
- **MFA параллельно, условия те же.** Как в основном бенчмарке, один вызов на диктора,
  `num_jobs = 1`, те же модели и параметры. Параллельно выравниваются только разные
  дикторы, каждый процесс в своей копии каталога MFA (`scripts/parallel_mfa.py`).
- **Запуск:** только при чистом дереве Git. Записываются состояние Git до и после,
  хэши кода и `uv.lock`, повторы MFA и хэши весов BRQE. Готовые прогоны не
  перезаписываются.
- **Метрики** — как в основном бенчмарке:
  - средняя ошибка границ слов: сначала среднее по высказываниям диктора, затем среднее
    по дикторам;
  - Acc@20ms;
  - покрытие слов: сопоставленные слова / эталонные слова;
  - число сбоев.
- **Статистика:** точный знаковый ранговый тест Уилкоксона по дикторам, поправка Холма
  внутри каждого режима. RTF записывается только для прозрачности.

## S2 — темп речи

- **Данные:**
  - все 160 высказываний TIMIT основного прогона;
  - 200 клипов Buckeye: по 10 на каждого из 20 тестовых дикторов, выбраны из замороженной
    тестовой выборки `reports/buckeye_test_sample_20260401.json` с seed 20261103.
- **Темп:** 0,8 / 0,9 / 1,0 / 1,1 / 1,25×.
  - Высота тона сохраняется. Метод — фазовый вокодер с фазовой привязкой к пикам
    (`scripts/tempo.py`), окно 512 отсчётов, шаг 128.
  - Отображение времени линейное: t' = t / темп. Эталонные границы пересчитываются так же:
    TIMIT — в отсчётах, Buckeye — в TextGrid с проверкой обратного чтения.
  - Темп 1,0 тоже проходит через вокодер. Это контроль обработки: сравнения идут с ним, а не
    с исходным прогоном.
- **Режимы:** все девять режимов бенчмарка для каждого корпуса и темпа, итого 10 прогонов.
- **Основные сравнения:** A2_proposed, A2_brqe, B2_proposed, B2_brqe — каждый темп против
  1,0. Ошибка сообщается в миллисекундах изменённой записи. Дополнительно — умноженная на
  темп, то есть в масштабе исходной речи.
- **Гипотеза:** к ускорению точность чувствительнее, чем к замедлению; в сценарии B больше,
  чем в A, из-за ошибок распознавания. Отказ от гипотезы публикуется так же.

## S3 — размер Whisper

- **Данные:** те же 999 клипов Buckeye основного прогона, только сценарий B: B0_whisper,
  B1_whisper_ctc, B2_proposed, B2_const, B2_brqe.
- **Модели:** tiny, base, small, medium, large-v3-turbo (faster-whisper, CUDA). Загрузка
  моделей одобрена автором вместе с S3. Базовый уровень — замороженный прогон с large-v3
  (`reports/buckeye/benchmark_utterances.json`), он не повторяется.
- **Основные сравнения:** B2_proposed и B2_brqe — каждая модель против large-v3, по дикторам.
  Покрытие слов сообщается для всех моделей.
- **Гипотеза:** ошибка границ после MFA зависит от размера модели слабее, чем покрытие слов,
  потому что MFA выравнивает уже найденный текст.

## Порядок и правила

1. Цепочка запускается отдельно от сессии: S1b (поправка 4) → S2 → S3. Анализ каждого
   подысследования идёт после его прогонов.
2. **Критическая ошибка** — падение процесса, нативный сбой MFA после повторов или
   расхождение хэшей. Она останавливает цепочку. Исправление идёт только через коммит
   с объяснением в этом протоколе, затем перезапуск с места остановки: готовые прогоны
   пропускаются.
3. Сбой отдельного высказывания или записи — не ошибка, а результат. Он сообщается.
4. Если к сроку подготовки статьи S2 или S3 не завершены, RQ4 сокращается до готовой
   части (план, §10.1).
